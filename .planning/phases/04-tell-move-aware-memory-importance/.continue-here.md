# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: applyAppraisal misattribution — `applyAppraisal()` (sim.js, ~804-835)
  hardcodes `event.actor` as the target of every relational/emotional consequence
  (trust/affection/grievance shifts, `pushEmotion`, `SeekRestitution` goal creation). That
  is correct for `Take`/`Attack`/`Give` (the actor did the thing to the witness/victim), but
  wrong for `Tell` — the actor is the *messenger*, not who the claim is about, and
  `applyClaimBelief` (sim.js ~1099-1122) already correctly routes a Tell claim's relational
  consequences to `claim.subject`. Letting `applyAppraisal` also fire on Tell (attributing to
  the messenger) double-counts the claim's emotional weight at the WRONG target. This is what
  flipped Phase 1's `positive-clone-attacks-player` regression check: `ives` ends up attacking
  `mara` (who gossiped to it) instead of `player` (who actually attacked `mara`). **Structural
  mitigation required, not yet applied**: give `appraiseEvent`'s return shape a generic
  `attributedTo` field — default `event.actor` (Take/Attack/Give unchanged), explicit `null`
  for Tell. `applyAppraisal` reads `appraisal.attributedTo` instead of `event.actor`
  everywhere inside it, and no-ops (skips ALL relational/emotional/goal work) when it's
  null/falsy. Memory-importance formation (`addMemory`) is untouched — it reads
  `appraisal.impact` earlier in `perceiveEvent`, before `applyAppraisal` runs.
- [ ] CONSTRAINT: the SAME bug will hit Move next — Plan 04-02 (not yet executed) adds a
  `Move` branch to `appraiseEvent` for D-04's causal flight detection, with a nonzero impact
  when a witnessed Move is a flight from violence. If `attributedTo` isn't ALSO set to `null`
  for that branch, witnessing someone flee will generate grievance and a `SeekRestitution`
  goal against the fleeing agent — for fleeing, which is nonsensical. Fix `04-02-PLAN.md`'s
  Move-branch action text to include `attributedTo: null` BEFORE that plan is executed, not
  after a second fixture flips.

**Do not proceed until both boxes are checked.**
