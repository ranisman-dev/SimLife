    resolved. It does not change the exit code.

**Exit code.** Exit 0 if and only if **all three** hold:
  1. every failing check is covered by an approved acknowledgement,
  2. `scripts/baseline.json` was present, and
  3. the baseline diff is empty.
Acknowledgement covers only named qualitative checks. It never excuses a missing baseline
and never excuses a non-empty diff. Otherwise exit 1.

Print, in this order:
  1. a header line naming the seed the run used (`Sim.DEFAULT_SEED`), so the output
     states its own reproducibility conditions;
  2. one line per entry in `result.checks`, formatted `PASS <name> :: <detail>`,
     `FAIL <name> :: <detail>`, or `KNOWN-MISMATCH <name> :: <detail>` per the rules
     above, plus any `STALE-ACK` lines;
  3. when `result.diffs` is present and non-empty, a `Baseline diff:` header followed
     by `Sim.formatDiff(result.diffs)` — the field-by-field, old-to-new rendering
     D-09.3 requires. Never dump raw JSON.
  4. a final `OVERALL: PASS` / `OVERALL: FAIL` line. When acknowledgements are in force
     and the run otherwise passed, print `OVERALL: PASS (N acknowledged mismatch(es))` —
     keep the literal `OVERALL: PASS` prefix so the string is greppable either way.

Missing-baseline behavior (plain run, no flag): print the check lines normally, then an
explicit line stating that `scripts/baseline.json` was not found and that
`node scripts/verify.js --update-baseline` captures the first one, and exit **1**. A
missing baseline is not a pass — the golden-master half of the check did not run — and no
acknowledgement changes that.

`--update-baseline` behavior (D-09.2, the golden-master re-baseline workflow — this
exists so a human reviews a diff and confirms an intentional change instead of
hand-editing JSON):
  - Run the check exactly as above and print everything above, **including the full
    baseline diff**, before writing anything. The human must see what they are about to
    bless.

    failing`, name `scripts/known-mismatch.json` and the Plan 02 Task 4 checkpoint as the
    only sanctioned path, write nothing, and exit 1. This is the executable form of "do
    not bless a failing baseline."
  - Otherwise write `JSON.stringify(result.snapshots, null, 2)` plus a trailing newline to
    `scripts/baseline.json`, print a confirmation line naming the path and how many diff
    entries were just accepted, and exit 0. A run with approved acknowledgements is
    allowed to write: the baseline records *behavior*, and Phases 2-7 need a reference to
    diff against regardless of whether that behavior matches PERSON-MODEL.md's prose.
  - The write happens **only** under the explicit flag. A plain failing run must never
    silently rewrite the baseline.
