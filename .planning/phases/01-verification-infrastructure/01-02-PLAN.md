**Scenario construction — two isolated worlds, one clone each.** Do NOT put both clones
in a single world. In a single world the victim reacts first (agent-list order puts
`mara` ahead of `ives` in `computeWitnesses`), her reaction cascade is witnessed by both
clones before either perceives the original event, and the qualitative assertion becomes
dependent on witness ordering — which Phase 2 (ORDER-01) is specifically going to
change. That would make Phase 1's own regression gate invert the moment Phase 2 lands.
Two isolated worlds running the identical script under the identical seed is the
controlled A/B that PERSON-MODEL.md:140-143 actually describes, and it is
ordering-independent by construction. D-09.1 is unaffected: each world's snapshot still
derives its participant set via `scenarioParticipants`, so the harness generalizes to
Phase 2's attacker/victim/multi-bystander case unchanged — the baseline is simply keyed
by scenario name.

Define a module-level `const CLONE_SPEC` holding the shared clone definition
(`personality`, `values`, the `CompetitiveJungle` weight magnitude, the clone agent id,
and the victim agent id). Build each variant like this:

  1. `const world = createWorld();`   — never modified (D-02); TESTING.md blesses it as
     the one legitimate fixture factory, so no new agent-construction export is needed.
  2. `world.driftEnabled = false;`    — VERIF-01's drift-off toggle. Read it back only

  3. `seedRng(world);`                — no second argument, so it uses D-04's hardcoded

     copy) and `mind.worldview` (deep copy) from `CLONE_SPEC`. The two variants receive
     `worldview: [{ belief: 'CompetitiveJungle', weight: +W }]` and
     `[{ belief: 'CompetitiveJungle', weight: -W }]` respectively — **identical in every
     other respect**. Use `ives` as the clone and `mara` as the victim; both already
     exist in `createWorld()`.
  5. Relocate every other NPC to `'away'` — derived, not enumerated: every agent that is

Name the two scenarios `jungle` (positive weight) and `averse` (negative weight).

**Checks — return them, never print them.** Build a `checks` array of
`{ name, pass, detail }` entries; top-level `pass` is the AND of every entry. Include at
minimum these five, using exactly these names:

  - `clone-specs-differ-in-exactly-one-field` — programmatically prove the two variants'
    applied clone state differs **only** in the `CompetitiveJungle` weight: deep-compare
    the two clones' `mind.personality` and `mind.values`, and compare their
    `mind.worldview` with that one weight normalized out. This check is what stops a
    later tuning pass from quietly making the divergence trivially true by changing two
    things at once.
  - `positive-clone-attacks-player` — in the `jungle` world there is an event with
    `verb === 'Attack'`, `actor === <cloneId>`, `data.targetId === 'player'`, and

    (sim.js:876) or on the `impact >= -0.05` early return that logs

**Return shape.** `{ pass, checks, snapshots: { jungle, averse } }`, where each snapshot
comes from `snapshotWorld(world)` with no explicit agent list so `scenarioParticipants`
