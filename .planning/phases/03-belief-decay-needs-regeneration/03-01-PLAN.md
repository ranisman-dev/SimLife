<objective>
Give beliefs the same lazy decay + self-prune-on-push lifecycle memories already have,
with one exemption: a belief contradicted by ground truth ("known false") is never pruned.

Purpose: `mind.beliefs` currently only grows — no decay, no pruning — which is the gap
DECAY-01/DECAY-02 close. `mind.memories` already solves this exact problem
(`memoryStrength()` + `addMemory()`'s filter-before-push), so this is a mirror, not an
invention.

**Scope boundary — deliberate, state it in the summary:** decayed confidence is consumed
by *pruning* and *display*. Decision-path reads of stored `belief.confidence`
(`findConflictingBeliefs`' `confidence <= 0.2` eligibility gate at `sim.js:829`,
`existingSupport` at `sim.js:845`, `believesDead`'s `confidence > 0.4` gate at
`sim.js:991`) are NOT rewired to the live accessor this phase. That mirrors
`memoryStrengthForEvent`'s own contract at `sim.js:503` — `// no memory record left =
genuinely forgotten` — where decay reaches decision logic by the record disappearing, not
by the gate reading a decayed number. Rewiring `believesDead` would make an NPC silently
forget a death at ~50 ticks, which no requirement asks for. Do not add `tick` parameters
to `findConflictingBeliefs` or `believesDead`.

Output: `beliefConfidence()`, `TUNING.beliefPruneFloor`, prune filters at both belief push
sites, `runDecayCheck()` with two DECAY-01 checks and two DECAY-02 checks, and the
verify.js wiring that makes them gate the exit code.
</objective>

Add `TUNING.beliefPruneFloor = 0.03` to the `TUNING` object at `sim.js:51`, with a comment

Add `function beliefConfidence(belief, currentTick)` immediately below `memoryStrength`
(around `sim.js:499`), mirroring `memoryStrength`'s formula shape exactly with
`belief.confidence` substituted for `mem.importance`: halflife of `3 + belief.confidence * 35`,
returning `belief.confidence * Math.pow(0.5, ageClamped / halflife)` where `ageClamped` is
`Math.max(0, currentTick - belief.tick)`. It must be a pure function of its two arguments —
no assignment to `belief` anywhere in the body, no caching, no write-back. Purity is
load-bearing, not stylistic: `snapshotWorld()` serializes raw stored values, so any
write-back-on-read would make the golden-master baseline depend on read order.

Add prune-on-push at both belief push sites, mirroring `addMemory`'s filter-immediately-
before-push shape. The filter keeps a belief if EITHER its `source` string includes the
literal substring `known false` OR `beliefConfidence(b, tick) > TUNING.beliefPruneFloor`.
Guard the source read against a missing/undefined `source` so the filter can never throw.
  - Site A: inside `perceiveEvent`, immediately before the `witness.mind.beliefs.push({...})`
    at `sim.js:602`. Use `event.tick` as the filter's tick.
  - Site B: inside `applyClaimBelief`, immediately before the `witness.mind.beliefs.push({...})`
    at `sim.js:892`. Use the function's `tick` parameter.
The `known false` substring is exactly what `applyClaimBelief` writes at `sim.js:898`
(`source: contradicted ? \`${source} (known false)\` : source`), and those beliefs are
pushed at `confidence: 0` (`sim.js:838`) — a naive floor-only filter would delete the single
most protective record in the mind, which is precisely what D-02 exists to prevent.

Do NOT add a length cap for beliefs. `addMemory` has `if (length > 40) shift()`, but
`shift()` removes the oldest entry unconditionally, which would evict a protected
`known false` belief and violate D-02. Add a comment at Site A recording that this
divergence from the `addMemory` template is deliberate and why.

Export `beliefConfidence` on the `Sim` object (`sim.js:1773`), placed beside the existing
`memoryStrength` entry — `presentation.js` will consume it in Plan 03-02, and
`presentation.js` reads engine state only through the public API per its own top-of-file
contract.

Do not touch `findConflictingBeliefs`, `believesDead`, or the confidence-discount writes at
`sim.js:856`/`859`. Those discount writes scale stored confidence and must NOT re-stamp
`belief.tick` — a downward revision is not reinforcement, so the decay clock keeps running
from formation. Add a one-line comment there recording that decision.
  </action>
