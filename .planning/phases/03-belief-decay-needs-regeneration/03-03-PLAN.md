<objective>
Give `belonging` its first mutator in the project's history: giving someone an item, or
vouching for someone, raises the *giver's*/*teller's* own sense of belonging.

Purpose: DECAY-04 and ROADMAP Phase 3 success criterion 4. `PERSON-MODEL.md` currently
records `belonging` as "wired to nothing anywhere — pure stub, permanently." This plan is
what makes that line false, and Plan 03-05 updates the doc accordingly.

**Two findings from `03-PATTERNS.md` that change the obvious implementation:**
1. **No coercion detection is needed and none must be built.** D-05's "no coercive framing"
   qualifier is already satisfied unconditionally: every `Give` in this codebase hardcodes
   `consented: true` (`sim.js:376`), and `parser.js:46-52` always produces plain
   `{targetId, item, quantity}` with no coercion flag anywhere. `Take` is the codebase's only
   coercive-transfer verb and always carries `consented: false`. The positive/coercive
   distinction is already `Give` vs `Take`.
2. **The guard direction flips.** Both existing `adjustNeed` hooks guard `!target.isPlayer`
   because they lower the *target's* need. These new hooks raise the *actor's* need, so the
   guard must be `!actor.isPlayer`. The player has `mind: null` (`sim.js:69`); copying the
   existing guard verbatim would throw `Cannot read properties of null` the first time a
   player gives someone bread.

Output: two guarded hooks in `applyEffects`, two `TUNING` constants, and three DECAY-04
checks including an explicit player-guard regression check.
</objective>
